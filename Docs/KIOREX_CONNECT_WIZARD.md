# Connect to Kiorex (Kiorly Clinic and Kiorly Nurse), ADR-040

Kiorly Clinic and Kiorly Nurse works fully on its own. **Connect to Kiorex** (`/kiorex/connect`) guides an organisation that started standalone through joining the marketplace later.

- **Checklist.** `GET /api/v1/kiorex/connect?clinicId=` returns the steps computed from real state, each `done | action_needed | waiting_kiorex | blocked`, with a deep link to fix it. Subscription, entitlement (`clinic.kiorex_listing`), a VERIFIED doctor, a bookable visit type with a fee, availability with slots, profile completeness (80 %), consent (terms version + fee acknowledgement; the fee sentence reads the published market schedule), optional telehealth or home visits.
- **Request.** `POST /api/v1/kiorex/connect/request` moves listings DRAFT -> PENDING_VERIFICATION and sends the signed, PHI-free request. The decision arrives on `PUT /marketplace/v1/connection/:orgRef` (signed marketplace API) and listings become LIVE automatically when every other gate is green. Organisations without `Tenant.providerSettings.kiorexConnect` (existing and imported ones) are legacy-connected and never gated; self-serve sign-up writes `STANDALONE`.
- **Enrolment code (contracts 1.9.0).** The "Request to go live" step asks for the one-time enrolment code Kiorex ops create for this organisation (Partner onboarding > Enrolment codes). The first request is signed with it; Kiorex answers with an intake key (shown once) which the product keeps sealed and signs every later request with (re-submit, credential rotation). The code is held in the form only and is never stored. Wrong, used, expired or revoked codes all answer the same way (`ENROLMENT_CODE_REJECTED`). The old shared-webhook-secret signing is gone. Protocol: INTEGRATION.md in the workspace root and `kiorex-contracts` 1.9.0.
- **Secrets.** No credentials are exchanged: Kiorex already holds the Clinic marketplace client.
- **Status.** The product polls Kiorex with a status token it derives itself (HMAC of the organisation id); nothing is stored. Rejection returns the organisation to standalone.
- **After Go live.** The page offers to make Kiorex Passport the default sign-in (`defaultSignInMethod`) and to invite staff to link their phone.
- **Tests.** ``kiorex-connect.node.test.ts` (API and web)`; end to end: `e2e/test/22-standalone-connect.e2e.ts` in the workspace repo.
- **Not done / needs a human.** Counsel-approved terms and fee wording, real notification providers, real launch-gate evidence, the production hand-over channel for enrolment codes.

## Front door: the state-aware Kiorex tab (ADR-040 amendment)

The nav item **Kiorex** (owner/admin; Lite owners reach it through the Admin tab) opens a front door that picks one of five states from real state (`GET /api/v1/kiorex/front-door?clinicId=`): NOT_CONNECTED (landing and Talk to us), IN_PROGRESS (progress and next step; the full checklist is at `/kiorex/connect`), WAITING (what happens next), LIVE (dashboard) and ATTENTION (paused, changes requested, rejected: decision banner plus what is missing). Live shows Kiorex bookings this month, attended and new patients, fees charged, rating (existing overview data), listings per doctor with pause/resume and recent Kiorex bookings (doctor, time, status, channel; no patient names). Writes: `POST /kiorex/front-door/{interest,start,talk}`; flags live in `providerSettings.kiorexConnect` (`wizardStartedAt`, `interestAt`, `lead`).
- **Wording.** All marketing text is the `kiorexMarketing` namespace (`apps/web/src/features/kiorex/kiorex-marketing-strings.ts`). **NEEDS_HUMAN: founder and counsel approve it before launch.** It states no price and no patient number; the fee sentence is built from the published fee schedule when there is one, otherwise it says the fees are confirmed by the Kiorex team.
- **Talk to us.** Inline form (no pop-up): name, role, phone and/or e-mail, preferred time, optional note, consent to be contacted. Sent signed to Kiorex (`POST /partners/v1/leads`, secret `KIOREX_LEAD_SIGNING_SECRET`, dev default outside production only); it becomes a lead in Kiorex ops > Partner leads. Viewing the tab while standalone and pressing Start connecting send one PHI-free funnel marker each (organisation id and product only).
- **Home card.** One dismissible card on the home dashboard for standalone organisations; dismissal is stored per user in the browser and the card returns only through "Show the Kiorex card again" on the tab.
- **Tests.** Unit: `kiorex-front-door.node.test.ts` (state mapping, form validation, signing) and the locale parity tests; Playwright `e2e/kiorex-tab.spec.ts` with `playwright.kiorex-tab.config.ts` (every state, widths 360 to 2560, Arabic RTL, dark, axe, home card); real stack: `e2e/test/24-kiorex-front-door.e2e.ts` in the workspace repo.
- **Not done.** The home-card dismissal is per browser, not stored on the user record (no schema change).
